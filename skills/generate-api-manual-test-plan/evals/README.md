# Evaluations

Lint cases for plans generated by this skill. The skill produces a markdown file, not callable code — so "eval" here means static assertions on the saved plan: does it have every section the skill promises, every helper, every guard, and zero unresolved placeholders?

## When to run

- **Always after generating a plan.** Run `evals/check-plan.sh <path-to-generated-plan>` before declaring the plan done. The check should exit 0.
- **Before publishing a new version of the skill.** Generate plans for each fixture case in `cases.jsonl` and run the checker against each. Any new check that catches a class of bugs the skill produced gets added as a case.
- **When a generated plan misbehaves at runtime.** Add a case that asserts the specific property that should have prevented it.

## Files

| File | Purpose |
|---|---|
| `cases.jsonl` | One JSON object per line. Each is a fixture describing a feature/service shape, the scenarios the plan should cover, and the structural assertions every saved plan must pass. |
| `check-plan.sh` | Static checker. Takes a path to a generated plan and the name of the case it was generated from. Greps for required sections and forbidden patterns, exits non-zero on any miss. |

## Adding a new case

When a generated plan ships with a defect, add a case:

1. Reproduce the conditions in `cases.jsonl` (service shape + scenario list).
2. Add the property that would have caught it to `expected.required_lines` (must-contain) or `expected.forbidden_patterns` (must-not-contain).
3. Re-generate the plan against the case until `check-plan.sh` exits 0.

## Eval philosophy

These are structural / lint checks, not behavioural ones. They confirm the **plan is well-formed**; running the plan against a real service is what confirms the **feature works**. Both layers exist on purpose.

A passing `check-plan.sh` only means "this plan won't fail in the boring ways the skill has failed before." It does NOT mean every scenario's assertion is correct or that the discriminator key actually appears on spans — those judgements need a human or a deeper agent.
